
# TECHNOLOGY SELECTION

## PRINCIPLE

Select the simplest suitable technology
for the project requirements.

Do not force a universal stack.

Inspect the existing repository first.

## FRONTEND

Possible technologies:

- React.
- Next.js.
- Astro.
- Vue.
- Svelte.
- HTML.
- CSS.
- JavaScript.
- TypeScript.

## STYLING

Possible approaches:

- Modern CSS.
- CSS Modules.
- Tailwind CSS.
- Existing project styling systems.

## ANIMATION

Possible tools:

- CSS transitions.
- Framer Motion.
- GSAP.

Use animation libraries only when justified.

## BACKEND

Possible technologies:

- Node.js.
- Existing backend frameworks.
- PostgreSQL.
- Supabase.
- Appropriate managed services.

## CMS

Possible solutions:

- Sanity.
- Strapi.
- WordPress.
- Existing CMS.

## ECOMMERCE

Consider:

- Shopify.
- WooCommerce.
- Established commerce platforms.
- Custom commerce only when justified.

## PORTABILITY

The skill requires no particular language or framework. Discovery and delegation
depend on the host platform: portable instructions do not guarantee native
execution on every agent. The delivery gate uses only the Python 3.9+ standard
library, so no native dependency has to be installed to run it.

## RULES

1. Inspect before selecting.
2. Preserve existing working infrastructure.
3. Prefer mature dependencies.
4. Avoid unnecessary complexity.
5. Verify compatibility.
6. Review maintenance requirements.
7. Document significant decisions.
8. Never install dependencies without a reason.

The Orchestrator approves major architecture changes.
