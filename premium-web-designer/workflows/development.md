
# DEVELOPMENT WORKFLOW

## OBJECTIVE

Implement the approved experience safely
and incrementally.

## PHASE 1 — INSPECTION

- Inspect the repository.
- Identify existing architecture.
- Check dependencies.
- Review available scripts.
- Identify constraints.

## PHASE 2 — PLANNING

Define:
- Component architecture.
- Page structure.
- Design tokens.
- Data requirements.
- Integrations.
- File ownership.
- Implementation tasks.

## PHASE 3 — FOUNDATION

Implement:
- Global styles.
- Typography.
- Color tokens.
- Layout primitives.
- Navigation.
- Shared components.

## PHASE 4 — PAGE DEVELOPMENT

Implement each page according to
approved UX and visual specifications.

Use real project content when available.

## PHASE 5 — FUNCTIONALITY

Implement:
- Navigation.
- Forms.
- Interactive elements.
- State management.
- API connections.
- Loading states.
- Empty states.
- Error states.

## PHASE 6 — RESPONSIVE

Review:
- Mobile.
- Tablet.
- Desktop.
- Intermediate widths.

## PHASE 7 — TECHNICAL VALIDATION

Run available:
- Build.
- Type checking.
- Linting.
- Tests.
- Browser validation.

## DEVELOPMENT RULES

Work in small increments.

Preserve user changes.

Avoid unnecessary dependencies.

Do not introduce unapproved architectural changes.

Report blockers immediately.
