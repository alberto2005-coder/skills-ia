
# DISCOVERY WORKFLOW

## OBJECTIVE

Understand the project before designing or coding.

## PROCESS

### 1. Request analysis
Identify:
- Website type.
- Business or product.
- Main objective.
- Target audience.
- Desired outcome.

### 2. Repository inspection

When an existing project is available:
- Inspect its directory structure.
- Identify the framework.
- Inspect dependencies.
- Identify existing components.
- Review current design conventions.
- Identify incomplete functionality.

Never overwrite existing work without understanding it.

### 3. Business analysis

Identify:
- Value proposition.
- Products or services.
- Competitive positioning.
- Conversion objectives.
- Trust requirements.

Do not invent business information.

### 4. Scope definition

Define:
- Pages.
- Sections.
- Features.
- Integrations.
- Required assets.
- Technical constraints.

### 5. Missing information

Ask only questions that materially affect
the project outcome.

Use reasonable documented assumptions
when appropriate.

### 6. Success criteria

Define measurable or verifiable acceptance criteria.

## DELIVERABLE

Create project-brief.md using:

templates/project-brief.md

## APPROVAL

The Orchestrator reviews and approves the brief
before creative direction begins.
