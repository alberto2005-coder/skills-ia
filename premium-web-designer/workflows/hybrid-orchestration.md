
# HYBRID MULTI-AGENT ORCHESTRATION

## OBJECTIVE

Coordinate specialists across different
AI environments.

## MODE A — NATIVE SUBAGENTS

When supported:

1. Orchestrator creates the plan.
2. Specialists receive independent tasks.
3. File ownership is assigned.
4. Dependencies are respected.
5. Deliverables are reviewed.
6. QA evaluates the implementation.
7. Orchestrator approves delivery.

## MODE B — SEQUENTIAL SIMULATION

When subagents are unavailable:

Execute the roles as independent phases:

1. Orchestrator.
2. Art Director.
3. UX/UI Designer.
4. Frontend Developer.
5. Backend Specialist.
6. QA Auditor.
7. Orchestrator final review.

Maintain separate responsibilities and deliverables.

Never pretend that simulated roles are
separate running agents.

## MODE C — PARTIAL DELEGATION

When some native agents are available:

Delegate supported independent tasks.

Simulate the remaining specialist roles.

Maintain a single shared project brief
and design system.

## PARALLEL EXECUTION

Safe parallel tasks include:
- Independent research.
- Separate page content analysis.
- Independent asset evaluation.
- Independent technical investigation.

Sequential tasks include:
- Finalizing design before implementation.
- Shared architecture modifications.
- Integration-dependent development.
- Final visual approval.

## FILE OWNERSHIP

Only one specialist should own a file
during a particular implementation task.

Other specialists provide recommendations
through task handoffs.

## COMMUNICATION

Every handoff must specify:

- Task.
- Context.
- Dependencies.
- Files.
- Deliverable.
- Acceptance criteria.
- Status.

Use templates/task-handoff.md.

## CONFLICT RESOLUTION

The Orchestrator makes final decisions.

Prioritize:
1. User requirements.
2. Security.
3. Accessibility.
4. Approved creative direction.
5. Usability.
6. Maintainability.

## FINAL APPROVAL

The QA Auditor reports independently.

The Orchestrator evaluates the report
and authorizes delivery.
